# OpenCode Human Answer — V3

OpenCode V2 全局插件，用于让 Coding Agent **动手前有交代、执行中有反馈、完成后说人话**。

## 本次改动

相比 V2 只约束最终答复，V3 新增三阶段沟通规则：

1. **动手前说明**：复杂或有风险的任务，第一次写入动作前先给用户可见的简短说明，说明会碰哪些文件／目录／数据表、做法和保护现有成果的措施；然后在授权范围内继续改。简单任务不必列计划。
2. **过程反馈**：只在重要发现、阶段性结果、方案实质变化或风险出现时更新，不逐项播报工具调用，也不反复申请普通操作的许可。
3. **结果汇报**：先说结论，分清修改、构建、启动、落库、验证和推测，说明写到哪一层（工作区未提交、已提交、已部署、已写入数据库），避免堆砌黑话；不虚构测试结果，不额外安排无意义的测试和构建。
4. **表达风格**：所有回复都适用的中文表达约束——先答问题再讲原因，说具体事实不堆抽象词，不输出调查流水账，技术细节按「决策 → 原因 → 调试」三层排序，禁止技术官话和机器味压缩表达。

规则里「动手」有明确定义，只指写入和状态变化：改文件与目录、改代码配置、装依赖、运行会写入的程序或命令、改数据库、调用改状态的接口、git 写操作、部署发布、改系统设置。读文件、搜索、看日志、只读查询、编译与跑测试这类只读验证不算动手，不需要先写说明。

提示词只强化行为，强制部分由「写入闸门」兜底，见下文。

原有插件 ID `human-answer` 保持不变，可以直接替换 V2。

## 运行原理

通过官方 `ctx.session.hook("context", ...)` 接口，在**主 Agent 的每次模型请求**前追加 system 指令，包括工具执行后的继续推理。它不会修改项目的 `AGENTS.md`，也不会修改用户输入、代码、工具参数或测试输出。

**重要限制**：`context` 钩子只是强化模型行为，不能独立保证模型一定在写入前输出可见消息，也无法拦截并重写模型已经发出的最终答复。真正强制的部分由下面的「写入闸门」完成。

## 写入闸门

通过 `ctx.permission.hook("evaluate")` 把写入类操作升级成权限确认（官方 API 里唯一能改判的钩子：`allow`／`ask`／`deny`）。两条规则：

- **硬闸门**：命令命中不可逆或对外可见的清单，无论模型是否已经说明，一律弹确认。清单包括 `git push|merge|rebase|reset|tag|clean`、`rm`／`Remove-Item`、`DROP|TRUNCATE|DELETE FROM|ALTER TABLE`、`docker push`、`npm publish`、`kubectl|helm|terraform|ssh`、`taskkill|sc delete|reg add`、磁盘类命令、发布部署脚本。
- **软闸门**：其余写入（改文件、`git add|commit`、装依赖、`Copy-Item`、`psql` 等），只在模型本轮没有先输出可见说明时弹确认。说明要 ≥16 个字符（中文一字算一个），"好的""我来处理"不算；文字必须排在工具调用之前才算。只读命令和只读工具不弹。

判定说明是否存在的依据是 `ctx.session.context()` 返回的消息里，最近一条助手消息在第一个工具调用之前的文本部分。OpenCode 若改了消息结构导致读不到 `parts`，软闸门自动放行、不误弹，硬闸门不受影响。

关闭闸门：`opencode.json` 里把插件写成对象形式并设 `"gate": false`，只保留提示词注入。

```jsonc
{
  "plugins": [{ "package": "~/.config/opencode/plugins/human-answer", "options": { "gate": false } }],
}
```

弹确认后模型会收到拦截说明（要求它先讲清目标、影响范围、回滚方式）。你可以批准继续，此时写入照常执行；拒绝则本轮停下。

**提示词体积**：当前整段约 13 KB，会在主 Agent 每次模型请求前注入，长会话下成本明显。若全局 `AGENTS.md` 已包含表达风格那一段，插件里的第四节属于重复注入，二选一即可。

## 安装（Windows）

将本工作区的 `index.ts` 复制到：

```text
%USERPROFILE%\.config\opencode\plugins\human-answer\
  index.ts
```

若已有 V2，只需用新的 `index.ts` 替换旧文件；原有其他插件与配置无需改动。重启或重新加载 OpenCode，**新建会话**验证。请先确认自己运行的是支持 `Plugin.define` 与 `session.hook("context")` 的 OpenCode V2；旧 V1 不适用。

## 验证建议（真实任务，不必额外跑无意义测试）

- 提出一个实际的多步骤分析或代码修改请求：观察第一次写入动作前是否先说明处理计划，并随后继续动手。
- 让 Agent 只做只读调查（读文件、搜索、只读查库）：观察它是否直接开始，没有硬凑开场白。
- 执行中出现新发现时：观察是否给出少量有信息量的过程反馈。
- 完成时：观察是否区分已修改、已验证和未验证。
- 再问一个简单问题：确认没有机械输出计划。
- 问一个纯分析问题（例如「这个开关是干什么用的」）：确认第一段直接给答案，没有先罗列查了哪些文件，技术细节排在结论后面。
- 闸门硬拦：直接说「提交并推送」，不给上下文。预期是推送前弹权限确认，拦截语要求模型先说清写入内容、影响范围和回滚方式。
- 闸门软拦：让 Agent 改一个文件，但先让它一句话都不说直接改。预期是第一次写入前弹确认；模型补完说明后重试即放行。
- 闸门不误伤：让它跑 `git status`、`git log --format=%h`、`node --check`，预期全程不弹确认。

验证多种模型和界面，因为是否支持先发可见文字、模型是否遵守规则，会受模型及 OpenCode 前端影响。

## 卸载

删除 `%USERPROFILE%\.config\opencode\plugins\human-answer` 文件夹并重新加载 OpenCode。
